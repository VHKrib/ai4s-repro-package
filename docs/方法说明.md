# 方法说明

本文件说明 a4s-repro 到底算了什么、每个数字怎么来的、以及它**不能**说明什么。
所有结论都能用包内文件复核，复核命令见 `证据索引.md`。

---

## 1. 这条链路在整体工作中的位置

A4S（AI4ScienceHackthon）把一次计算药物设计拆成三段：

| 段 | 职责 | 本包中的位置 |
|---|---|---|
| 01 编排层 | 理解需求、分派任务、汇总结果 | 不在本包内（SciencePal / Biology Agent 是外部服务，见 `docs/桥接报告.md`） |
| 02 结构准备 | 晶体结构 → 干净的受体/配体 → READY_FOR_03 交付 | `src/module02-portability-win/`（Windows 适配副本，原件未改） |
| 03 评估决策 | 对接、几何/一致性检查、打分排序、判据决策 | `src/stage3-agent/` + `scripts/` |

因此本包能独立跑通的是 **02 适配副本 + 03 全链路 + 一个真实案例**；01 只以
`docs/桥接报告.md`（联调实录）和 `scripts/sciencepal_bridge.py`（桥接脚本）的形式留证。

## 2. 案例：HIV-1 蛋白酶 × Darunavir（1T3R）

选这个案例而不是继续用 JAK2，是因为它把整条链路压进了一个**自证型**实验：

* 结构是 1T3R（HIV-1 蛋白酶野生型二聚体 + TMC114/darunavir 共晶，分辨率 1.20 Å）；
* 配体就是晶体里的配体本身（HETATM `017`）；
* 于是"把配体对接回它自己的晶体构象"这件事有一个**客观标准答案**：重对接 RMSD。
  如果流程（质子化、PDBQT、盒子、打分）有任何一步错了，RMSD 会立刻变大。

这不是在找新抑制剂，而是在证明"这条链路的每一步都还对"。

## 3. 计算步骤（`scripts/run_pipeline.py` 逐步执行）

1. **输入校验**：`cases/.../case.json` 里记录了 1T3R.pdb、PubChem 模板 SDF、vina.exe
   的 sha256；任一对不上就直接停（不让"看起来能跑"掩盖输入被换掉）。
2. **结构拆解**（`prep_inputs.py`，science 环境）
   `gemmi` 读 1T3R，按记录级过滤只留 `ATOM`、链 A+B、altloc 空|A → 1 496 个蛋白原子；
   取出 `017` 残基的重原子坐标；盒子 = 共晶配体重原子 AABB 每轴各加 5.0 Å。
   → center (19.459, 29.766, 14.159)，size (20.361, 20.806, 18.122) Å。
3. **受体制备**（`prep_receptor.py`，`meeko mk_prepare_receptor`）
   侧链只建模到 CB 的残基（A:7, A:41, A:43, B:41, B:43）映射为 ALA 以匹配模板；
   加极性氢、Gasteiger 电荷、AutoDock 原子类型 → 1 811 原子的 `1T3R.pdbqt`（315 个极性氢）。
4. **配体制备**（`prep_ligand.py`）
   先用 `rdDetermineBonds` 从晶体坐标推连接性，再把 PubChem CID 213039 的**键级**按
   图同构映射贴上去（16 个等价映射取第一个），得到 C27H37N3O7S、
   InChIKey `CJBJHOAVZSMMDJ-HEXNFIEUSA-N` 的 `cocrystal_pose.sdf`——这就是重对接的参考构象。
   加显式氢后用 `meeko mk_prepare_ligand` 生成 42 原子、14 个可旋转键的 `darunavir.pdbqt`。
5. **真实对接**（`dock_vina.py` → `scripts/shim/vina.py` → `tools/vina_1.2.5_win.exe`）
   Vina 1.2.5，vina 打分函数，exhaustiveness 8、num_modes 9、seed 42、cpu 4。
   9 个姿势的分数被原样记录（从 `REMARK VINA RESULT` 读，不经任何插值）。
6. **重对接 RMSD**（`scripts/a4s_redock.py`）
   每个姿势 `meeko mk_export` 回 SDF，再用 RDKit `rdMolAlign.GetBestRMS`（对称性感知）
   对 `cocrystal_pose.sdf` 求 RMSD。最好的姿势（pose 1）RMSD = 0.211 Å。
7. **stage-3 全链路**（`src/stage3-agent/`）
   intake（输入契约校验）→ applicability（方法与参考对照）→ poses（vina 引擎再对接一次）
   → qc（几何/一致性）→ rank（打分排序）→ decide（判据）→ export（固定格式产物 + 清单）
   → `validate` 重读全部产物并重算 sha256。
8. **逐项比对**：把第 5–7 步的真实输出与 `case.json → expected` 对比，全中才 `verdict=OK`。

## 4. 参考数字（2026-10-30 首次真实运行，本包重跑必须一致）

| 项 | 值 |
|---|---|
| 姿势数 | 9 |
| 最佳对接分 | **−9.958 kcal/mol** |
| 9 个姿势分数（pose 1→9） | −9.958 / −9.148 / −8.877 / −8.782 / −8.366 / −8.233 / −7.946 / −7.880 / −7.810 |
| 重对接 RMSD（pose 1） | **0.211 Å**（阈值 2.0 Å） |
| 盒子 center / size | (19.459, 29.766, 14.159) / (20.361, 20.806, 18.122) Å |
| 受体 PDBQT 原子数 | 1 811（含 315 极性氢） |

| stage-3 validate | 10 个产物全部通过 |

## 5. 限制（读结果前必须知道）

1. **对接分不是亲和力。** −9.958 kcal/mol 是 Vina 打分函数的值，与实验 Kd/IC50 没有可比性
   标定关系。它只能用来在同一协议、同一受体下做**相对**比较。
2. **这是 redocking，不是发现。** 配体就是晶体配体本身，低 RMSD 证明协议能复现已知姿势，
   **不**证明任何分子有活性。
3. **单受体、刚性、单协议。** 没有突变 panel、没有柔性侧链、没有 MD、没有 MM/GBSA、
   没有 AF3、没有重复种子统计。这些在 `result.json → not_run` 里都是 `NOT_RUN`，不是 0。
4. **02 原件未改。** 包内只有 Windows 适配**副本**（改动仅为 `as_posix()` 与换行），
   原交付的 `PACKAGE_SHA256SUMS` 仍原样通过；差异见
   `docs/02_UPSTREAM_DEFECT_write_manifest.md`。
5. **平台差异。** 02 模块原批准环境是 macOS arm64 + CPython 3.11.9。Windows 上重跑属
   跨平台组合；化学结果一致（行尾归一化后核心产物逐字节相同）但**未经上游验证**。
6. **`scripts/run_pipeline.py --mode jak2` 需要外部 02 交付**（约 217 MB，未随包分发）。
   只跑 HIV-1 案例不需要它。
