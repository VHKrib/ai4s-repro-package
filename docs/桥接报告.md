## 失败点与踩坑（如实记录）

1. **initiate 的 `sandbox_id` 返回 null**，与「返回 `{sandbox_id, thread_id, agent_run_id}`」的前置认知不符：`sandbox_id` 键存在但值为 null（sandbox 在 run 内部创建，不同步回传）。**未重发 initiate**，改由 `GET /api/thread/{thread_id}/sandbox` 找回。
2. **sandbox 归属端点路径此前猜错**：`/api/sandboxes`（列表）404、`/api/threads/{id}` 404、`/api/agent-run/{id}/sandbox` 404。正确路径是**单数** `thread`：`GET /api/thread/{thread_id}/sandbox`。首轮探测共 4 个 404 + 1 个 422，全部记在日志里。
3. **`GET /sandboxes/{sid}/files` 与 `/files/content` 的 `path` 是必填 query**，缺了直接 422（`{"loc":["query","path"],"msg":"Field required"}`）。
4. **`POST /sandboxes/{sid}/files` 是 `{path, file}` 两段 multipart**：`path` 是 sandbox 内目标全路径（如 `/workspace/result.json`），文件字段名 `file`，可选 `overwrite`。只传文件不传 `path` 会失败。
5. **`/files/content` 返回 `application/octet-stream` 裸字节**（不是 JSON 包裹）。桥接脚本第一版把 body 当 JSON 反序列化再 `json.dumps` 写回，导致 20485B → 16729B、sha 不符；已改为「仅当 content-type 含 json 才解包，否则原样保留字节」。修正后 sha256 才与本地一致。**这是本次唯一一次自查出的错误实现**。
6. **本机 CA bundle 环境变量指向不存在的文件**（`D:\Postgres SQL\ssl\certs\ca-bundle.crt`），首轮所有 HTTPS 直接 OSError、0.0s 失败；脚本已内置自愈（检测到无效路径就回退 certifi），该修复留在脚本里。
7. SSE 事件里同一段正文出现两次（`type=assistant` 一次、`assistant_response_end` 里的 chat.completion 一次），脚本按去重后输出（565 → 282 字）。
8. `/api/agents` 返回 200 但列表为空 —— 不是 403，属另一种资源；真实 agent 目录在 `/api/agent-catalog`。

## 限制

- **网页端能力不在本 key 权限内**：会话列表、网页侧消息发送、dashboard 一律 403（服务端原话）。本次**未尝试**，桥接也不提供对应子命令。也就是说「在 SciencePal 网页会话里发消息」这条路走不通，可用的只有 SDK 面（catalogs / agent / run / sandbox）。
- **文本只能从 SSE 取**：`GET /api/agent-run/{id}` 响应里没有文本字段（只有 `id/threadId/status/startedAt/completedAt/error/modelName/executionState/executionStartedAt/recovery`）。好在 run 结束后 `stream` 仍会重放全量历史（200，~1s），所以「先跑完再取文本」可行，不必并发抓流。
- **单次联调**：仅 1 个 run、1 个 sandbox，未覆盖失败态（failed/stopped）、未覆盖大文件、未覆盖 `agent_selection_explicit` 之外的路由（`/api/agent/routing/*`）行为。
- 传上去的两个文件留在 sandbox `/workspace/` 里（未删除，sandbox 是否自动回收由服务端策略决定）。
