# A4S-02-MODULE-001：把已通过的JAK2准备流程封装为02可调用模块

## 阶段目标

先完成02自身的工程收口：接收一份任务配置和01原始材料，自动生成受体、参考配体、搜索盒和结果清单。当前批次只支持已经审阅的6VGL/JAK2/RXT配方，不要求01或03现在参与。

## 已确认依据与边界

- A4S-02-SMOKE-001-R1的固定JAK2准备包独立内容核查通过；详见随附审阅记录。
- 固定对象：6VGL模型1；蛋白auth A/label D；RXT auth A:1201/label H。
- 已批准的本轮配方：仅排除明确注释为表达标签的825–839；保留840–1132和PTR1007；采用NASP/CGLY/PTR−2及已记录OXT建模方法；干式刚性受体；原RXT包围盒每面padding5 Å。
- 这是smoke_test用配方，不是任意结构可自动套用的科学规则。
- 现有解释器和RDKit/Meeko/Gemmi环境可用，不升级依赖。
- 原项目位置、AGENTS.md、Git状态由执行时检查；旧工程及原包不覆盖。
- 原包的job.json继续作为输出契约基础。若需要加字段，保持向后兼容并记录。
- 未运行Vina，03状态待联调；SciencePal全链路、JAK1和新候选设计均未验收。

## 输入与输出

输入建议是一份JSON（具体文件名按现有工程调整），包含：
- schema_version、job_id、mode；
- 目标标识；源CIF、FASTA及01交接说明的相对路径和哈希；
- 模型号、蛋白auth/label链、参考配体comp/auth/label/残基号；
- 引用一个已经批准的prepare_profile及其版本/摘要；
- 搜索盒方法、padding和单位。

科学处理策略保存在版本化配方中，不让任意字符串触发删除残基或改变化学状态。
缺少必要信息或输入超出本配方支持范围，返回BLOCKED/2；不要静默采用其他链、WT或位点。

输出：沿用job.json和现有科学文件；附只读校验、日志、输入与配方摘要。正常路径最终READY_FOR_03/0；技术执行或文件完整性错误FAIL/1；资料或支持范围不足BLOCKED/2。失败不得残留误导性的READY状态。

## 执行顺序

### 1. 复用现有实现，补一个统一入口

优先调用或提取module02-smoke、module02-smoke-r1中已经运行过的函数。
不要重写化学流程，不建Web服务、不增加Agent或新Skill。
入口的预期形式例如：

```sh
python -B scripts/run_prepare.py --request cases/jak2_6vgl.json --out runs/jak2_001
```

这是要实现的接口形式，不表示该文件已存在；有等价入口时沿用。
CLI读取一个请求，按批准配方执行，最后输出结构化状态和结果位置。进度日志单独保存，不能混淆最后状态。
输入相对路径以请求文件所在目录解析；输出路径相对各自job/manifest所在目录解析，写清这两条规则。
运行代码不依赖作者的/Users/cityu目录或相邻EvidenceScope。

### 2. 从原始材料生成，而非复制旧成品

新运行目录起初仅有配置、原CIF、FASTA、01说明、配方及必要的冻结参考定义。
不得复制旧receptor/ligand/reference/box成品来充当本次新生成结果。

自动完成：
- 输入与结构身份核对；
- 应用已批准的去标签/端基/PTR配方并准备受体；
- 从指定CIF实例提取RXT，核对化学键与手性，生成reference.sdf；
- 复用先前实现的配体准备代码，完成ligand.sdf与ligand.pdbqt；
- 从实际参考坐标计算搜索盒；
- 内容校验、job与清单输出。

若原配体提取代码在旧module02-smoke中存在，优先复用。
如依赖CCD，只复制或获取明确的原始化学定义并保存来源/版本/哈希，不把旧准备后SDF伪装为原始输入。

### 3. 分离科学比较与运行元数据

相同输入、配方和锁定环境下，核心科学产物应可重复。
时间、解释器绝对路径、运行目录、job_id等可能变化；不能仅因此认定化学结果失败。
保留这些元数据，但分别评价：
- 核心文件字节一致（适用时）；
- 关键化学身份、坐标与参数一致；
- 来源、状态与产物关联正确。
不修改原R1报告或既有复现标准，只在新模块版本明确新规则及理由。

### 4. 增加轻量的接收检查

保留完整科学内容检查，用于02生成结束时验收。
另提供一个标准库即可运行的只读检查入口：只核对路径安全、必需文件、哈希、任务状态、受体/配体/搜索盒绑定。
该检查成功明确标为INTEGRITY_PASS或等价含义，不能声称重新验证了质子化或结构科学正确性。
缺少科学运行依赖时，统一入口给出明确错误，不输出READY。

### 5. 只做与封装风险直接相关的测试

A. 真实正常路径：空输出目录，从上述原始资料一条命令完成全流程，日志证明真实执行了受体与配体准备。
B. 路径迁移：在不同目录（可含空格）运行，不需要相邻旧项目；比较核心科学结果和正确的元数据。
C. 输入不匹配：临时副本改变链选择或源哈希，明确非零退出，不能自动选择别的对象；本批不开展新的科学处理方案。
D. 新输出文件被篡改：轻量只读检查发现不一致，检查前后文件未变。
E. 已存在输出：拒绝覆盖或使用明确的新run目录，不能混用旧结果。

可以复用已有测试。不要复制大量与本批无关的旧日志来充实新包，也不测试无关UI样式。
